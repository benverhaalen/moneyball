# Data tooling reviewed in October 2026

Review cutoff: **2026-10-07**, current October availability, not a forecast of October 26 releases. Primary documentation and public contracts were inspected. Competitors were not authenticated, benchmarked or installed. No current best forecaster or measured competitive edge is established by this review.

The decision to improve is a manager asking on Tuesday, “Should I add anyone?” Moneyball must know the actual rules, acquisition options, future service lost by a drop, and fresh role/status evidence. More scraped pages alone do not solve those gaps. Keep Sleeper/ESPN authoritative for league state and reuse the existing NFL warehouse for completed opportunity; use optional tools only for a missing decision input.

## Different mechanisms and where they fit

| Tool/family | Inspected mechanism | Useful job for Moneyball | Tradeoff and discriminating test |
| --- | --- | --- | --- |
| Firecrawl Alexandria | Free tool-contract discovery; structured provider execution through one API, with listed credits and provider terms. FFToday exposes weekly stat lines and explicit period/preset options. | Optional forecast challengers plus focused injury/report evidence. Implemented adapter described separately. | Access convenience does not certify units, freshness, rights or independent authorship. Test correct week, complete custom-scoring components, candidate coverage and whether new evidence changes a legal choice. |
| Exa | Search with domain and publication-date filters; source URLs, content/highlights, request ID and reported cost. | Find primary team announcements and structurally relevant strategy research. | Search relevance is not a verified injury probability or structured player ledger. On the same changing-role cases, measure primary-source recall, latency and dated evidence capable of reversing the advice. |
| Tavily | Search with domain restrictions, news mode/date filters, publication-date options and usage receipts. Basic/fast/ultra-fast cost 1 API credit; advanced costs 2. Automatic parameters can promote depth, so pin it when budgeting. | Alternative to Exa for focused current news; choose one after a representative comparison. | Returned publication dates/snippets still require source inspection. Compare both on the same cases and dollar/credit cost; avoid paying for two nearly identical retrieval paths by default. |
| Crawl4AI | Self-hosted browser crawling with CSS/XPath/regex schema extraction; repeated extraction can run without an LLM. Repository specifies Apache-2.0. | A focused permitted-page fallback when no usable structured API exists. | Browser dependencies, selectors and operations become our maintenance burden; code license does not grant publisher data rights. Test saved page variants, null fields and layout changes; fail on schema drift instead of returning confident empty tables. |
| Apify | Versioned Actor execution, run/build IDs, private datasets, runtime controls and charging limits in its run API. Store Actors package existing extraction workflows. | Managed extraction for a genuinely missing source without running a browser fleet ourselves. | Actor-specific input/output, pricing and rights require inspection; a marketplace listing is not a reliable NFL feed. Pin a build and test complete candidate coverage, failed-run behavior and receipts against the same source. |
| SportsDataIO | Documented weekly/season player projections, defense/IDP endpoints, injuries/depth charts/news and stable provider player IDs. Dictionary identifies nullable and scrambled fields and Eastern-time timestamps. | Strong candidate if incomplete stat components or identity/status reliability prevent meaningful comparisons at scale. | Subscription/access and actual field coverage need verification; some legacy docs contain old week bounds, and test/scrambled fields cannot drive live decisions. Obtain an authorized sample and test exact custom scoring, current week coverage, timestamps and unresolved identities before buying or replacing a source. |

## Choice and reference transfer

**Use the existing Alexandria contract instead of building six scrapers.** The small stdlib adapter keeps the core install portable. Its producing path discovers the full contract and price, refuses ambiguous/per-record cost, performs one bounded request, and retains raw receipts separately from qualified forecast rows. This transfers the library's contract-first mechanism rather than merely attaching its brand name. Revisit if exact capability discovery fails, live schema differs, or coverage/credit cost is unsuitable.

**Use search for changed opportunity, not numeric projection extraction.** Exa and Tavily are competing news-discovery candidates, not automatic replacements for a structured forecast. A future adapter should retain article publication time, original URL, first local observation and player/event binding; a generated search answer should never overwrite status. Adopt one only if a focused test finds fresher decision-relevant sources than available host browsing at acceptable cost.

**Treat ingestion like measurement instrumentation.** A fresh HTTP response proves a measurement was retrieved, not that the underlying quantity changed. The implementation preserves observation and local-availability times, rejects wrong periods and stale observations, expires quantitative rows, and carries issue-time limitations into compact outputs. Requalifying old data cannot refresh its age. This mechanism transfers from measurement and historical evaluation to prevent look-ahead and stale-source confidence.

**Use a value-of-information policy.** Fetch the fact with a plausible chance of changing the action: starter assignment, injured teammate's availability, remaining-week workload or the proposed drop's retained value. A blanket refresh of six correlated rankings is a poor substitute for that fact. Save pre-decision snapshots and evaluate against hold plus the native platform policy using the same legal candidate pool and costs. This remains a strategy hypothesis until demonstrated prospectively.

**Keep a maintained extraction fallback and a licensed feed as separate options.** Crawl4AI/Apify answer “can we collect this permitted page?” SportsDataIO answers “can we obtain a stable structured sports contract?” Choose the latter if recurring incompleteness is causing withheld comparisons; choose the former only for a focused missing source whose access and maintenance economics justify it. Neither warrants replacing existing nflverse history or Sleeper/ESPN state.

No third-party implementation code was copied, and no competitor was installed. Package licenses and data permissions remain separate. Current public documents do not establish that the NFL released all advanced tracking data; selected official releases and existing nflverse coverage still require dataset-specific interpretation.
