# A compact context for the live driver

This is the operating brief for a fresh live driver after setup has been completed and independently checked. It does not replace source research or certify an optimal pick. The user makes every real-draft selection. Only explicitly assigned private mock controls are authorized for autonomous practice.

## Separate setup from the clocked session

A setup worker prepares the authenticated private browser, exact league configuration, verified player identity mapping, tested controls, local dossier index, source hashes and first-turn alternatives. Preserve a compact setup receipt. The clocked driver should receive that receipt and the tested helper's command contract; it does not need thousands of lines of browser markup or verifier implementation in its context. Recheck the receipt and actual room/turn rather than accepting an unverified setup claim. Start a fresh driver before START, never by pausing an active mock to regain context.

Only one live Sleeper mock on this account should run at a time until the observed cross-mock pause behavior is resolved. Research and offline critiques can run concurrently. Never pause, intentionally enable Sleeper Auto-Pick, undo picks or change the clock. Report a failure immediately and retain it for both control and decision critique.

## Fixed objective and required comparison

Improve feasible championship opportunities this year and in subsequent years. Current projected points are an intermediate; age, ADP, source count and raw variance are not dynasty utility. Use the actual ten legal starter jobs, ordinary/taxi/IR constraints and held assets. A future opening must be earned. A favorable trade is not guaranteed.

Compare A now plus a credible later acquisition against B now plus its corresponding later acquisition. State the current contribution gained/lost and the specific future or acquisition assumption that orders the routes. Use coherent provider components separately. If those assumptions do not resolve the choice, give an explicitly uncertain preference and the condition favoring the alternative. Do not invent championship percentages.

Keep an acceptable branch if all preferred later names disappear. Record when that condition happens and reconsider its cost. A named reserve's own NFL vacancy is not the same event as our starter missing time. Future taxi/IR promotions and replacement acquisitions consume real capacity; count their obligations without assuming their outcomes.

## Keep data on disk, decisions in context

Persist complete observations, all squads, source documents and action receipts. Return only the actual room and turn, countdown, own roster, recent opponent selections, computed next own picks, changed dependencies and a compact 12–24-candidate slate plus watched players outside it. A captured slate is not proof every candidate was analyzed.

Read the serious player's full case once when necessary. Later queries retrieve the particular source passage that can change the comparison. Do not reprint the entire board or previously read dossiers after each pick. Maintain a short durable ledger: actual holdings, current legal service gaps, future replenishment obligations, common failure scenarios, prepared branches and their invalidators. Detail remains accessible by source path/hash; compression must not turn missing data into zero or discard contrary evidence.

Prepare immutable branch content between turns, not just a timestamp claiming preparation. The `draft_fastlane` compiler is intended to validate previously authored branches quickly; it supplies no independent player ranking. New eligible players outside the analyzed slate, lost prerequisites, revised evidence or a changed roster send the affected comparison back to reasoning. Losing one member of an acceptable substitute group need not invalidate every branch.

## Clock discipline and communication

At our turn, check the fresh actual board and validate all actionable alternatives. Reject stale text that still recommends a taken player. Confirm exact room, current turn, manual mode, roster, full pick prefix and candidate identity. Public API fetch time alone does not establish board freshness.

By roughly 30–35 seconds, stop expanding the investigation. Use the best still-valid prepared branch with appropriate confidence, or state the unresolved choice explicitly. Aim to publish by 45 seconds and leave the manager time to choose within the one-minute target. These are tested objectives, not guarantees. If every prepared branch is invalid, say so; do not disguise a stale recommendation as a fast one.

Use a short live message: first choice and relative confidence; up to two genuine alternatives with the condition favoring each; the decisive waiting/replacement cost. Keep the full comparison and sources in the receipt. Do not repeat an essay about all general dynasty principles at every turn.

For mocks, save the exact recommendation before the timestamped click attempt, then independently verify actual player ID and the new roster. Share a unique attempt ID across events. Record first observed turn time separately from final guard freshness; visible clock and observation intervals provide timing bounds. A failed run still gets a complete critique of every deliberate choice, using the board available then. Automatic selections are separately attributed.
